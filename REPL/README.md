# DCS Lua nREPL Client

Компактный интерактивный CLI-терминал для кооперативной отладки и рантайм-выполнения Lua-кода внутри игрового движка DCS (Unity). Спроектирован на основе бинарного протокола **OpenGOAL nREPL** и сетевой архитектуры **RosEngine**.

---

## 🚀 Возможности (Features)

* **Интеллектуальный многострочный ввод:** Терминал автоматически анализирует синтаксис Lua (`function/end`, `if/end`, таблицы и баланс скобок). При нажатии `Enter` он переносит строку на `...`, если блок кода не завершен.
* **Бронированный рантайм:** Полная защита от нативных падений Unity (`PANIC: not enough memory`). Ошибки синтаксиса и рантайма перехватываются, изолируются в `pcallk` и выводятся в консоль.
* **Бинарный протокол:** Данные упаковываются в пакеты с фиксированным 8-байтным заголовком (Длина + Тип), что гарантирует атомарную доставку кода любого размера без потерь.
* **Встроенная навигация:** Поддержка истории команд стрелочками `Вверх/Вниз` и встроенные служебные команды.
* **Кроссплатформенная палитра:** Промт (`lua>`), результаты вычислений (золотой) и ошибки (светло-красный) подсвечиваются нативными средствами `.NET`, без использования ломающихся ANSI-строк в Windows.

---

## 📑 Описание протокола (nREPL Protocol)

Протокол обмена данными является **бинарным, синхронным иLittle-Endian**. Данные передаются через raw-TCP сокет (порт по умолчанию: `49155`).

### 1. Структура пакета (Packet Layout)

Каждое сообщение (как от клиента, так и от сервера) состоит из **строгого 8-байтного заголовка** и опционального тела (Payload):

| Смещение (Байты) | Тип данных | Назначение | Описание |
| :--- | :--- | :--- | :--- |
| `0x00 - 0x03` | `uint32` | **Payload Length** | Точный размер тела сообщения в байтах ( Little-Endian ). |
| `0x04 - 0x07` | `uint32` | **Message Type** | Идентификатор операции (ID команды). |
| `0x08+` | `byte[]` | **Payload** | Тело сообщения. Текст в кодировке UTF-8 (без `\0` на конце). |

### 2. Таблица типов сообщений (Message Types)

| ID (uint32) | Имя команды | Направление | Описание |
| :--- | :--- | :--- | :--- |
| `0` | `Ping` | Клиент ⇄ Сервер | Проверка связи. Сервер возвращает `Ping` с текстом приветствия или `pong`. |
| `10` | `Eval` | Клиент → Сервер | Запрос на выполнение Lua-кода. В ответ возвращается пакет `Eval` с результатом. |
| `20` | `Shutdown` | Клиент → Сервер | Сигнал закрытия сессии. Сервер немедленно освобождает сокет. |
| `30` | `CheckComplete` | Клиент → Сервер | Запрос проверки завершенности блока кода (проверка на `<eof>`). |
| `31` | `StatusComplete` | Сервер → Клиент | Ответ: "Код синтаксически завершен, можно отправлять на `Eval`". |
| `32` | `StatusIncomplete` | Сервер → Клиент | Ответ: "Блок кода не закрыт (открыт `if`, `function` или скобка). Ожидание ввода". |

## 🛠️ Команды консоли (CLI Commands)

Все команды терминала нечувствительны к регистру и могут вводиться как с двоеточием, так и без него:

* `help` или `:help` — Вывести встроенное окно справки и горячих клавиш.
* `clear` или `:clear` — Полностью зачистить текущий экран консоли.
* `ping` или `:ping` — Проверить сетевую задержку до виртуальной машины Unity.
* `exit` или `quit` — Безопасно разорвать TCP-соединение и закрыть терминал.

## 💻 Сборка клиента (Publish)

Чтобы скомпилировать `REPL.cs` в один независимый `.exe` файл, которому не нужны установленные среды выполнения на целевой машине, выполните в папке проекта команду:

```bash
dotnet publish -c Release -r win-x64 --self-contained true /p:PublishSingleFile=true /p:PublishTrimmed=true
```

Полученный файл `REPL.exe` можно положить напрямую в папку `Assets/Tools/` вашего Unity-репозитория.
